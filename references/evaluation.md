# 行为评估场景

维护 Skill 时使用这些隔离的合成证据检查实际产出。评估指令为“根据以下已读取记录生成剧情路线图 JSON，并说明覆盖范围”。向被评估模型提供场景输入与 Skill，将预期结果留给评估者。若要衡量改进，使用同一模型和输入分别运行无 Skill、有 Skill 两次并比较结果。此文件提供用例定义，实际执行情况单独记录。

## 重复选择、合流与回跳

输入记录均来自同一生效脚本，目标与命令已经解码。

```text
story.ks:10  入口 -> menu_day1
story.ks:20  menu_day1 玩家选择
             「去中庭」 -> 信赖点数 += 2，体力 -= 1 -> talk_a
             「留在教室」 -> talk_a
story.ks:30  talk_a 对白“她说明明天仍会在这里等候。” -> menu_day2
story.ks:40  menu_day2 玩家选择
             「去中庭」 -> ending_a
             「留在教室」 -> menu_day1
story.ks:50  ending_a，结束命令 END_A
```

预期保留两个独立玩家决策点和四条原文选择边，共用 `talk_a` 的稳定 ID，回跳指向第一天决策点。可从入口到达有结束依据的结局。第一天两条选项箭头进入同一个 talk_a 剧情框；只有第一天的「去中庭」旁显示“信赖点数 +2”和“体力 −1”。第二天的同文选项单独保留。入口只以无标签箭头连接第一天的选择点。若草稿另有“入口 → talk_a”且依据只是章节顺序，应移除。若脚本另有明确的条件跳转直接进入 talk_a，则保留该箭头并显示条件。

## 条件结局、EXTRA 与未解 GRAND

```text
main.ast:10    入口 -> 判定 bond >= 3
main.ast:20    条件为真 -> “两人约定来年重逢” -> END_A
main.ast:30    条件为假 -> “独自离开故乡” -> END_B
main.ast:40    END_A 与 END_B 均有明确片尾转换
title.ast:12   clear_A 为真时启用 EXTRA，目标 after_a
main.ast:41    END_A 完成时写入持久字段 clear_A = true
title.ast:18   GRAND 按钮跳转 grand_open，按钮启用条件尚未解码
grand.ast:10   grand_open 为 GRAND 篇入口，后续尚未读取
```

预期条件节点的两条出口为自动流程，分支剧情分别归属对应出口。EXTRA 的解锁依赖有明确脚本依据。GRAND 保留独立内容与观察到的标题入口，报告启用条件和后续内容未知。不能凭名称认定其已抵达真结局或推定需要同时完成 A、B。若宿主要求 `grand` 节点具备终结证据，先以场景节点表达该篇入口并记录限制。

## 多版本与覆盖缺口

```text
批次 original/index.json，原版 scene.ks:20
  玩家选项「帰る」 -> ending_home，已读取结束命令
批次 patch/index.json，汉化版 scene.ks:20
  玩家选项「回家」 -> ending_home，已读取结束命令
启动配置 load.cfg:8 明确 patch 覆盖原版同名资源
patch/scene.ks:30 有已确认的独立玩家菜单，其文字、条件和目标均未解码
patch/scene.ks:40 有动态跳转，其目标未知
patch/999.ks 只有场景正文，未见结束命令
```

预期以汉化批次为生效集合，原版与汉化版的同一菜单只计一次。已知选项保留“回家”原文。另一个已确认菜单保留未解析决策点和覆盖缺口，未知边等待补证。最大编号文件保留为普通场景。结果明确是部分路线，不能宣称完整覆盖。

## 多级主线与短分支

入口选择可以立即进入一个结局，也可以沿主线继续经过数个选择点，每个选择点又有自己的短结局。让入口的主线选项在窄窗口中换行，并同时检查默认折叠和全部展开。

预期短结局紧靠各自的分岔点。主线展开到更深处时，只有与相邻分支实际共用纵向空间的内容才需要拉开。检查标签能完整显示、连线清晰且节点和标签互不重叠。对照用例见 GalGear 的 `src-tauri/src/route_window/tests.rs`。

在 GalGear 中进一步检查提交字段、成功观察编号和原始来源指针。合成行号可用于本评估的证据描述，生产提交必须换成实际工具记录。

## 存档和合流选项

用两条先合流再按累计数值分流的个人线验证选线。分别点击两条线，核对原文选项、箭头、路线切换及恢复全图。加入旁挂和串联的旧存档节点，检查定位落在已有剧情上，原选项与后续剧情仍然连通。

## 标题重开后的菜单

用一个结局写入全局标记、下一次标题开始才出现的两级菜单验证。分别检查空标记、已通关后首次拒绝、第二次拒绝和两次确认。确认共有分支与独立结局的实际落点，只有逐步核验且写明通关前提的走法显示攻略。再放入一条含推断边的旧攻略和同样读取持久状态的 EXTRA，检查旧攻略降级为可能路径，EXTRA 仍从其真实标题入口触发。

## 收起普通剧情

用一条长共通线和一条线内还有选择的个人线验证。分别查看开始到首个决策、两次决策之间、以及最后一次决策到结局。打开箭头详情检查场景顺序和证据，比较投影前后的选项原文及路线高亮。测试在收起场景中定位存档，以及存在单出口条件、跨分支合流或回跳时的保留行为。
